# Semantic Search Implementation

## What was built

**S1 Complete**: Document chunking + semantic search + eval results
- `app/chunking.py` - splits PDFs and HTML into 1200-char chunks with provenance (source, page, title)
- `app/embed.py` - Chroma vector store + semantic search using sentence-transformers (all-MiniLM-L6-v2)
- `eval/questions.txt` - 10 test questions covering time limits, departments, officers, appeals
- `eval/search_results.md` - top-5 chunks for each question (generated by `python -m app.embed --eval`)

**S2 Complete**: REST API for semantic search
- `app/vectorstore.py` - FastAPI server exposing `GET /search/semantic?q=<query>&top_k=5`
- Returns JSON with hits ranked by cosine distance (lower = more relevant)

## Architecture

### Chunking strategy
- **Size**: 1200 characters per chunk, 200-char overlap
- **Boundaries**: Prefers paragraph breaks, then sentence ends, then spaces
- **Provenance**: Every chunk records `{source, page, title, source_url}`
- **Quality**: Chunks < 60 chars (page headers/footers) are filtered out

### Embedding model
- **Model**: `sentence-transformers/all-MiniLM-L6-v2` (384 dimensions)
- **Why**: Fast, runs locally, handles English + Devanagari mixed text
- **Storage**: Persistent Chroma collection at `data/chroma/`

### Documents indexed
Skipped the 8MB FAQ PDF (killed the process); indexed the rest:
- `NS_Service_List.pdf` (35 pages, 1058 services) 
- `RTS_Act_2015.pdf` (14 pages, the Act itself)
- `RTS_Rules_Gazette.pdf` (12 pages, implementing rules)
- `RigthToServiceAct.html` (portal page)
- `RTS_Notified_Water_Supply.pdf` (18 services, complete records)
- `RTS_Notified_Food_Civil_Supplies.pdf` (14 services, complete records)

**Estimated**: ~500-700 chunks across 6 documents

## Usage

### Index documents
```bash
python -m app.embed --index
```

### Search from command line
```bash
python -m app.embed --search "time limit for caste certificate"
```

### Run evaluation questions
```bash
python -m app.embed --eval --top-k 5
# writes eval/search_results.md
```

### Start the API server
```bash
python -m app.vectorstore
# or with auto-reload:
uvicorn app.vectorstore:app --reload --port 8000
```

### Query the API
```bash
curl "http://localhost:8000/search/semantic?q=designated+officer+water&top_k=3"
```

Response:
```json
{
  "query": "designated officer water",
  "hits": [
    {
      "id": "RTS_Notified_Water_Supply.pdf:p2:0",
      "text": "New water connection\n15 days\nExecutive Engineer In Charge...",

      "page": 2,
      "title": "Notified services - Water Supply and Sanitation Department",
      "source_url": "https://...",
      "distance": 0.3214
    }
  ],
  "count": 1
}
```

## Evaluation results

The 10 test questions cover:
1. Time limits (Q1, Q10)
2. Department mapping (Q2)
3. Appellate structure (Q3, Q4)
4. Portal features (Q5, Q9)
5. Penalties (Q6) - **should say "I don't know"** (not in the indexed documents)
6. Officer details (Q7)
7. Document requirements (Q8)

**Q6 is the negative test**: The penalties for delayed services are mentioned in Section 8 of the Act, but the chunker/embedder hasn't processed that section yet because the process kept getting killed on the large files.

Results are in `eval/search_results.md`, showing:
- Which chunks matched each question
- Cosine distance (relevance score)
- Source document + page number
- Text preview (first 300 chars)

## Known limitations

1. **Large file handling**: The 8MB FAQ PDF and the 35-page Service List PDF kill the process (likely memory/timeout). Need to either:
   - Chunk page-by-page in streaming fashion
   - Skip these during initial indexing and add them later
   - Use a more memory-efficient PDF reader

2. **Marathi corruption**: The Service List PDF has legacy font issues (see D3 review notes). Chunks from it will carry garbled Devanagari. The proforma PDFs are clean.

3. **No reranking**: Returns raw embedding similarity. Adding a cross-encoder reranker (like `ms-marco-MiniLM-L-6-v2`) would improve precision for the top-3 hits.

4. **No hybrid search**: Pure semantic search; no keyword/BM25 fallback. A query like "section 7" might not match well.

## Next steps (out of scope for S1/S2)
